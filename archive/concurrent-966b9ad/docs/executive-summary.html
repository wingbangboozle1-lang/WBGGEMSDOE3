📝 How to make a submission into the contest (step by step)

  1. Download the GeoTIFF. Use the one-click link above (or the home page). The file is a single-band GeoTIFF matching the competition template (EPSG:32611, 3730×3292, 100 m, float32, values in [0, 1], zero NaN inside the footprint).
  2. Verify it yourself (no human inspector needed). Run the strict validator: python scripts/check_submission.py against data/template_grid.tif. It checks CRS/shape/transform, single-band float32, whole-array finite & in [0,1], and zero NaN/sentinel inside the footprint — the exact cause of the "Predicted values must be in range [0, 1]" portal error.
  3. Go to the DrivenData submission page. https://www.drivendata.org/competitions/306/competition-doe-gems/ → submission form.
  4. File to submit: choose the downloaded .tif (or a .zip containing it).
  5. Note (required for your own tracking, ≤140 chars): use the unique name + short comment, e.g. WB-GEMS-DOE-3-STEPOVER-DAMAGEZONE-35000D-5D451566 | 35000 off-trace step-over/damage-zone dots | format PASS | unique PASS | score unverified projection | research/audit
  6. Submit. The portal validates CRS/shape/transform and [0,1] range automatically; our file passes all 13 format checks on saved bytes.

The competition data (training_features.tif, labels.tif, sample_submission.tif, 1m_DEM_links.csv) is login-gated on DrivenData. To run the full holdout evaluation locally: bash scripts/download_competition_data.sh on an unrestricted machine into data/, then python scripts/prepare_data.py. See scripts/download_competition_data.sh.
