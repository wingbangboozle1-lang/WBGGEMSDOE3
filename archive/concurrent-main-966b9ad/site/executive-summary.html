Purpose

This page reviews the highest-scoring submissions reported on the GEMSDOE sites listed in the brief, identifies the best submission to use as a starting point, and states clearly whether each is a unique submission (not an exact duplicate of another focus-site submission). It also links to our own generated TIF and explains how to submit it to the DrivenData GEMS competition.

Scores are as reported on each site. They have not been independently re-scored by us and are not organiser-confirmed for our submission. Treat them as historical reference only.

Among the focus sites, GEMSDOE32 (0.2778) reports the highest score. However, its "-zeros" suffix and the prevalence of "-nan" / "-zeros" submissions across many sites indicate that several of these files would fail the competition's validation gate (predicted values must be in range [0, 1] and no NaN inside the footprint). A "-nan" file cannot be submitted as-is.

Best submission to build on

GEMSDOE32 h33-h33-2-b2-...-zeros (0.2778) is the highest-reported score, but it is not a safe submission to copy: it is flagged "-zeros" (degenerate) and is not unique vs the "-zeros" pattern used across GEMSDOE36, 37, 39–44. Copying it would produce a duplicate submission.

Instead, our generated submission targets the same high-scoring neighbourhood (stepover / tip / relay-ramp density, cf. GEMSDOE33's h33d tip-stepover at 0.2632) through a unique method: H-NEW-01 "Blind stepover / relay-ramp pull-apart density" derived from DEM curvature texture plus local lineament density around visible faults. It is not a copy of any GEMSDOE 24–36 submission.

NOT OK to submit to the real competition as-is. This is a format-valid stand-in produced on synthetic test data. It passes every format gate (single band, [0, 1], no NaN) but its geometry does not match the real competition grid. To produce a scorable submission:
  1. Download real competition data via the DrivenData data tab (login required) into data/raw/.
  2. Create data/raw/REAL_COMPETITION_DATA_CONFIRMED.
  3. Run python scripts/prepare_data.py then python scripts/generate_submission.py.
  4. Upload the validated TIF to the DrivenData submission page.

4. Submission warnings (read before uploading)

  • The DrivenData form returned "Predicted values must be in range [0, 1]" for out-of-range / NaN rasters. Our validator rejects NaN and enforces [0, 1] automatically.
  • Every submission needs a unique name and an optional note (max 140 chars), e.g. "clustering with k=25". Our run card proposes note: Unique blind stepover/relay-ramp density (H-NEW-01); not a copy of any GEMSDOE 24-36 submission.
  • The file must match the submission format's CRS, shape, and geotransform — use sample_submission.tif as the reference grid.
