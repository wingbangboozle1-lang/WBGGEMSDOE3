It passes every format gate below, but its geometry does not match the real competition grid. To get a submission that can score, run the pipeline against real competition data (see How it works).

2. How it works

  1. Data: place competition rasters in data/raw/ (requires DrivenData login; see scripts/download_competition_data.sh).
  2. Prepare: python scripts/prepare_data.py writes data/manifest.json (CRS, shape, transform, dtype per raster).
  3. Generate: python scripts/generate_submission.py builds a favourability raster from the top-ranked hypothesis (H-NEW-01 blind stepover / relay-ramp density), conforms it to sample_submission.tif, and writes submission/*.tif.
  4. Validate: scripts/submission_writer.py / src/validate.py runs the validation gates below and writes a JSON report.
  5. Submit: upload the TIF to the DrivenData submission page with a note (max 140 chars).

3. Validation gates (no human inspection needed)

The generated TIF must pass ALL gates before it is considered OK to submit:

  • Single-band GeoTIFF
  • No NaN / inf inside the footprint
  • All values in [0, 1]
  • CRS / shape / geotransform match the competition reference grid (sample_submission.tif)

Any failure is a hard block: the file is flagged NOT OK to submit. This replaces manual human inspection with automated, project-level validation.
