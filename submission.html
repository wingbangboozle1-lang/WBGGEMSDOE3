Submission steps for a future `promote` candidate

  1. Check the selector decision first. The run card and executive summary must both say `promote` / “OK to submit.” Download only the exact file whose SHA-256 is recorded in that card. Do not select a historic TIFF or rename/convert it after validation.
  2. Confirm the automatic validator passed. The validator must check the entire required footprint for NaN/Inf and values in [0,1]; verify one band; compare CRS, width, height, and affine transform against the actual sample_submission.tif; and report all checks. A visual inspection is not a substitute.
  3. Open the DrivenData competition page and choose Submit. Sign in to the authorized account. The portal action is not performed by this repository; the current account quota is not visible here.
  4. Choose the exact file. Use the validated single-band .tif, or a .zip that contains exactly one GeoTIFF. The page's upload form described in the prompt labels this field File to submit.
  5. Enter the run-card name and note. Use a unique name, and paste the short differentiating comment from the run card (maximum 140 characters). Example format: HYP-ID | method | dot budget | run hash | verdict. Do not reuse the example as a real submission note.
  6. Review and submit only if the selector authorizes the slot. Respect the current competition rules and weekly cap. Keep the submission-page receipt, organizer score, exact artifact hash, and timestamp together. Only then may the score be labeled ORGANIZER-CONFIRMED.

Required automatic checks before any download button is enabled

Numeric values

Range and finiteness

Check all submitted prediction cells for finite values within [0,1]. Separately verify no NaN or infinity occurs inside the valid competition footprint. Record the outside-footprint policy and make it consistent with the template.

Georeferencing

Exact sample-grid match

Compare single-band count, CRS, rows/columns, and affine transform with the actual competition sample. A matching CRS alone is not enough.

Scientific gates

Holdout and uniqueness

Require the prescribed fold-local spatial holdout, single-feature leakage canary, pre-placement surface correlation audit, and final-dot overlap audit before a separate selector can promote the file.

Evidence and access limitation

The submission requirements above are transcribed from the user-provided competition description and form text. The DrivenData host and rule PDF were not fetched directly in this sandbox. Review the official competition page, problem page, and NLR guidance PDF before an actual portal submission.

Automated validation can remove the need for a person to inspect pixels, but an authorized account holder still has to choose the competition slot and complete the portal upload. No login, receipt, or quota information is available to this project.
