Official DTI and raster contract

Verified on the DrivenData problem page, 2026-10-28.

The competition uses a distance-weighted Tversky index with α=0.2, β=0.8, and a linear triangular kernel with 300 m support (three cells at 100 m). This makes the official task a fault-prediction task; it does not make a fault prediction proof of geothermal vent presence.

The published format requires a single-band float32 GeoTIFF, EPSG:32611, 100 m, matching bounds, values in [0,1], with data outside the bounds null or NaN. These written requirements are not proof of portal acceptance.

Parallel-run and leakage protocol

  1. Stay in one assigned method lane and reuse the shared cached feature stack, evaluate_holdout.py, and submission_writer.py; never fork shared tools.
  2. Before placement, check surface rank-correlation against registry rasters; stop if |Spearman| >0.90. After placement, stop and log a duplicate if more than 70% of final dots are within 3 px of any registry raster.
  3. Hold out whole fault segments with a buffer; derive catalogue-based features only from visible faults; pixel-exactly mask visible faults; pool DTI with α=0.2, β=0.8 and the 300 m triangular kernel.
  4. Test each feature alone for leakage. AUC >0.90 is leakage until an independent explanation is established.
  5. Every real score needs evaluator version, withheld-positive count, and 95% CI; public leaderboard values and projections are separate. A projection is never a score.
  6. Maximum three geological experiments or two hours; no real slot selection in this lane. A separate selector checks the weekly cap.
