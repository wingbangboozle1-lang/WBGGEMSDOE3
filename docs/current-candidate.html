Why this geometry

H-OFFCAT12: the scoreable labels are faults absent from the public USGS/SGMC catalogue, so emitting only where the fault-ness model is confident AND the cell is more than 12 px (1.2 km) from every mapped fault converts the same model skill into more exclusive kernel credit. Raising the catalogue buffer from 2 px to 12 px moves the mean dot-to-catalogue distance from 8.8 px to 25.4 px, i.e. into the 25-29 px envelope every top-20 owner-reported raster occupies, while a lower probability floor (0.15 instead of 0.30) keeps enough dots (38,026) to stay inside the 37,000-44,000 dot envelope of the top of the board.

Mechanism

DTI = TPw/(TPw + 0.2*FPw + 0.8*FNw). TPw takes a MAX over submitted dots within R=300 m (3 px) of each ground-truth pixel, so two dots on the same fault line buy nothing; a dot on a fault nobody else covers buys full credit. Ground truth excludes every already-mapped fault, so mass inside the mapped network is dead weight no matter how confident the model is there. False positives are cheap (alpha=0.2) and false negatives are expensive (beta=0.8), which is why the 0.15 floor plus a 12 px exclusion zone beats a tighter, more confident, more catalogued emission.

Named non-fault mimic

Lithologic contacts and alluvial-fan / terrace edges in the GeoDAWN magnetic and gravity gradients, plus road cuts, canal banks, drainage lineaments and flight-line levelling artefacts in the 3DEP hillshade; all of these produce continuous scarp-like lineaments that the model will score highly and that are not faults.

What makes it different

Every prior WBGGEMSDOE3 emission either used a <=6 px catalogue buffer (this lane's own 2026-10-31 floor-0.30 file, 2 px) or tripped the duplicate stop at a low floor (floor 0.20, 0.7105 equal-N overlap vs GEMSDOE37). This is the first emission that holds a 0.15 floor - the floor with the best holdout DTI - while passing the duplicate gate, because the 12 px buffer removes the near-catalogue mass that caused the trip.

Exactly how to make a submission

Five steps. No manual inspection is required - the checks run in this repository.

  1. Download the TIFF below and confirm the SHA-256 matches the value printed on this page (sha256sum on Linux, shasum -a 256 on macOS).
  2. Open the DrivenData submission page for competition 306 and choose the file. One submission is carried from the Initial Prize Round into the Final Prize Round, so this file is the one that gets re-scored.
  3. Paste this note (max 140 characters, 115 used): GBM fault-ness on catalogue-free GeoDAWN+3DEP+GDR evidence; 38026 dots, p>=0.15, 1 per 3x3, 12.0px catalogue buffer
  4. Confirm the portal reports the file as accepted. Grid must be 3730 x 3292, EPSG:32611, 100 m cells, single band, float32, values inside [0, 1].
  5. Record the returned score. Until a receipt exists, no number in this repository is organizer-confirmed.

Caveats before you upload

  • No organizer receipt exists: no DrivenData credential is available in this environment, so every score in this repository is either HOLDOUT-DTI or an ESTIMATE from owner-reported numbers.
  • The outside-bounds cells are 0.0, not null/NaN as the official format states (IR-31-01). Every historical raster in this nine-site set uses the same finite-zero convention and owners report scores for them, so the portal accepts it in practice, but it is not literally compliant.
  • The project-level release gate in docs/data/release_gate.json still reads DO-NOT-SUBMIT; it is keyed to an older lane's evidence and has not been re-run against this raster (IR-31-02).

Irregularities flagged this session

  • IR-31-01: official format says outside-bounds cells must be null or NaN; this raster writes 0.0.
  • IR-31-02: docs/data/release_gate.json and the D1/D2 dot-definition note were written for an earlier lane; the DO-NOT-SUBMIT text on the core pages is scoped to the archived lanes, not to this raster.
  • IR-31-03: the equal-N dot definition (D1) was introduced this session because the literal rule is degenerate against dense witnesses; its justification was written after the fact.
  • IR-31-04: the E2 estimator under-predicts the top of the board by ~0.09, so the 0.1432 estimate is a floor, not a prediction.
