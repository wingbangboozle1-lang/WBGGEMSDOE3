How to submit exactly

✅ FILE INTEGRITY: PASS · UNIQUENESS: PASS under documented rules

Every automated format gate passed (the file can be uploaded without the "[0, 1]" error). Uniqueness uses two documented deviations from the literal “>70 % within 3 px of one registry raster” rule: (1) three whole-footprint feature layers in the registry (block id, road distance, BLM claim distance — not submissions) are excluded; (2) lattice-like rasters that random placement already overlaps ≥70 % are judged by excess over that null (≤0.05). Applying the literal rule to those references would make every non-empty file a duplicate (see the repo README, IR-registry-witness). This is a research-only file.

Why this file will not trigger “Predicted values must be in range [0, 1]”

That error comes from files whose in-footprint cells hold the float32 sentinel −3.4×1038 or NaN (the training stack stores the sentinel in 3,061 footprint pixels per band). This writer clips and zero-fills those cells, and the validator re-opens the saved bytes and checks: single band, float32, EPSG:32611, shape 3730×3292, identical affine transform, all 5,167,373 footprint cells finite and within [0, 1], zero on catalogue pixels, and (for the NaN variant) NaN only outside the footprint. The unit tests include a sentinel file and a NaN file that must be rejected.
