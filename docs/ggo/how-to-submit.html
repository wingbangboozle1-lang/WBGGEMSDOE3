How to submit into the competition, exactly

Steps

  1. Open the submission page (login required): https://www.drivendata.org/competitions/306/competition-doe-gems/submissions/
  2. Click Choose file and pick wbggems3-ggo-covergate-60000d-20261031T012630Z-e7c02e69-zeros.tif — a single-band GeoTIFF, or the .zip containing exactly that one TIFF.
  3. Optional note field, paste: GGO lane: cover-gated gravity-gradient x basement-step x strain concordance, 60000 dots, off-catalogue, h=0.0675 vs SGMC
  4. Submit. The portal validates CRS/shape/geotransform and the [0,1] range, then scores against the public test chunk.
  5. Record the receipt score on this repo's run card; a receipt outranks every estimate here.

Requirements transcribed from the official problem page

  • same projected CRS as the training data — UTM zone 11N, EPSG:32611
  • same resolution as the training data — 100 m
  • same bounds as the training data; data outside the bounds is null or nan
  • a single layer, float32, values between 0 and 1 = confidence of fault presence

Root cause of “Predicted values must be in range [0, 1]”

Reproduced deterministically from this site's own bytes, no guesswork:

  • Every file the desk published on 2026-10-29 with NaN outside the footprint fails a whole-array range test: NaN is not ≥ 0 and not ≤ 1, so any validator that compares all values rejects it. wbg3-h2-scarp-thermal-20261029T134448Z-35040fda.tif carries 7,111,787 such cells and is what the executive-summary page linked as the download.
  • The -zeros encodings (0.0 outside, no NaN anywhere) pass: the same support with zeros instead of NaN has 0 out-of-range values. That is why the top sibling files are named …-zeros (GEMSDOE32 0.2778, GEMSDOE36 0.2750).
  • Two further defects found in the old archive and fixed here: wbggems3-blind-basin-interior-15000d…-zeros.tif put all 15,000 dots outside the footprint (so the scored region was empty), and wb-gems-doe-3-latest-submission-zeros.tif leaked 747 positive cells outside the footprint. The writer now refuses both by construction.

Note on the spec conflict: the prose says outside-bounds may be null/NaN, while the observed validator behaviour rejects it. We therefore ship zeros-outside (finite, in-range, no mass outside) — it satisfies the range rule and the bounds rule simultaneously. Flagged as IR-31-04 for organizer clarification.
