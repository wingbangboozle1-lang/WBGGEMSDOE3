Knowledge base

A concise reference for distinguishing fault evidence from convenient raster geometry, and scientific validation from public score reporting. Every statement about this checkout is scoped to the files and sources actually reviewed.

Core mapping concepts

TermWorking meaningImportant caveat
FaultA fracture or zone of displacement in bedrock, potentially expressed by aligned geophysical contrasts, topographic displacement, or seismicity.A linear feature is not automatically a fault. Lithologic contacts, drainage, roads, survey edges, alteration, and processing artifacts can mimic fault-like traces.
Catalogue / known faultA fault or fault segment represented in the provided label/catalogue data and masked according to the official scoring rules.The exact catalogue source and scoring mask must be read from official inputs and organizer rules. Do not infer the mask from filenames or public geology maps.
Magnetic responsePotential evidence of spatial changes in magnetic properties, possibly caused by lithologic boundaries or structures.Magnetic edges are non-unique: source depth, remanence, field direction, rock type, and processing affect the pattern. An edge alone is not a fault label.
Gravity responsePotential evidence of density contrasts and subsurface geometry.Basin fill and unfaulted lithologic contacts can produce gravity lineaments; agreement with independent structure is useful but not proof.
LineamentA mapped or raster-derived linear pattern that may be tested as a candidate structural trace.Lineament detection is a hypothesis generator. It requires confounder tests and spatial holdout validation before emission.
Emission / dotsThe discrete positive cells saved in a final candidate raster after any thinning, ridge tracing, or packing.Final dots and the continuous pre-placement surface are distinct validation objects: compare the surface before placement and the dots after placement.

Evidence labels (use literally)

  • HOLDOUT-DTI: spatial hide-and-recover score from a named evaluator, with withheld-positive count and 95% interval. It measures the stated holdout, not the organizer's hidden test.
  • ORGANIZER-CONFIRMED: a score copied from an archived organizer submission receipt bound to the uploaded file. A public leaderboard line or owner README is not a private submission receipt.
  • OWNER-REPORTED: a score asserted by a project owner without the reviewed organizer receipt. All nine historical focus-site scores currently shown use this label.
  • Projection: not a score; do not publish as a result. This site makes no new-score projection.
  • BYTE-VERIFIED: a file hash, raster grid, finite/range property, or mask relation recomputed from exact saved bytes. Byte verification does not establish score causality.

Spatial holdout and leakage checks

  1. Withhold whole fault segments with a spatial buffer; do not random-split neighboring pixels.
  2. Construct every catalogue-derived feature from visible faults only, inside each fold. Mask visible fault pixels exactly before evaluation.
  3. Evaluate pooled distance-weighted Tversky with the specified alpha=0.2, beta=0.8, and 300 m triangular kernel using the canonical shared evaluator.
  4. Test each feature alone as a leakage canary. AUC above 0.90 is treated as leakage until explained with evidence.
  5. Report evaluator version, withheld-positive count, and a 95% CI with every HOLDOUT-DTI result. A holdout is a research instrument, not a leaderboard prediction.
  6. Compare the continuous surface against the full registry before placement; compare final dots against that same registry after placement. Stop if absolute Spearman exceeds 0.90 or more than 70% of candidate dots lie within 3 pixels of any registry raster.

These protocol values are retained from the project prompt. The official competition metric and catalogue treatment should be checked against the organizer's pages before a future experiment.

Raster handling and release gate

  • The inspected nine historical TIFFs are single-band float32, EPSG:32611, 3730 × 3292, affine transform (100, 0, 243350, 0, -100, 4508550). These values describe the audited files, not an assumed replacement for the official sample template.
  • A future output must match the official sample template's band count, data type, shape, CRS, and transform; save every stored value finite in [0,1], use exact zero outside the valid footprint, and omit a NoData tag unless the official format requires otherwise.
  • Run scripts/validate_submission.py against the official template and labels after writing the file. Reopen the saved bytes, not only the in-memory prediction.
  • A validator pass does not establish holdout superiority, leakage safety, uniqueness, weekly-slot availability, or submission authorization. The run card remains the source of the release decision.

Known data and provenance limits

  • The official training features, labels, sample submission, existing-fault mask, and shared cached feature stack are not present in this checkout. No experiment was run here.
  • The precise assignment lane is absent from this session. A lane recorded in a sibling Arena branch is not transferable; see IR-002.
  • The nine historic scores remain owner-reported; the two selected historical variants from GEMSDOE30 and GEMSDOE33 contain non-finite cells outside the finite footprint.
  • The nine focus-site winners fail the stated pairwise final-dot overlap threshold against other focus winners. This is a subset audit, not the full registry check required of a future candidate.
  • Official USGS, DOE GDR, and competition pages are listed with access status on the Sources page. An unverified URL is not treated as proof of coverage or availability.
