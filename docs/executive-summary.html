Why a sparse H33-B2 file could outperform a denser raster

The competition metric is distance-tolerant: nearby predictions can earn partial credit, so multiple neighboring pixels may add false-positive mass without materially increasing coverage of a hidden fault. Removing low-marginal-credit pixels can therefore improve the precision/coverage tradeoff. The H33-B2 mask is byte-verified as a strict subset of the D2.8 mask, but the exact score attribution is not organizer-confirmed and no private labels or official TP/FP/FN breakdown are available. This mechanism is plausible, not established causality.

How to make a competition submission (only after a future green release)

Current state: stop here. There is no file to upload. Do not upload the audit links above or a file from another GEMSDOE repository under this project's name.
  1. Wait for a separate release decision. The landing page must show green “OK TO DOWNLOAD AND SUBMIT”, link one exact TIFF, and publish a run card with a SHA-256. A format-only pass is not enough.
  2. Download that exact `.tif`. Check that its SHA-256 matches the run card. The current project does not have such a file.
  3. Open the official DrivenData competition page and choose its new-submission form. Use the authenticated account; this static site cannot log in, upload a file, or see your private weekly cap.
  4. Select the TIFF in “File to submit”. The competition accepts a single-band GeoTIFF or a ZIP containing one GeoTIFF, per the form text supplied in the project brief. Prefer the tested TIFF directly unless the form requires otherwise.
  5. Enter the short note. Use the exact note in the run card, no longer than 140 characters, so the model/method/hash are traceable.
  6. Submit only if the separate selector approves a weekly slot. Save the organizer's submission receipt and the exact uploaded file hash. Record a number as ORGANIZER-CONFIRMED only from that receipt.

Automatic validation before any future download

The saved-byte preflight rejects non-finite pixels anywhere (including outside the footprint), values outside [0,1], CRS/shape/transform mismatch, and overlap with the provided known-catalogue mask. A second checker computes pre-placement Spearman and final-dot overlap against every hash-pinned entry in a supplied complete registry manifest; it requires the literal lattice and all nine focus winners and has no exemptions. The canonical full registry and a candidate are absent here, so uniqueness remains unmeasured. Neither script claims a score or authorizes a slot.

python -m pip install -r requirements.txt
python scripts/validate_submission.py candidate.tif \
  --template data/sample_submission.tif \
  --labels data/labels.tif \
  --out reports/preflight.json
python scripts/validate_registry_uniqueness.py \\
  --surface candidate-surface.tif \\
  --candidate candidate.tif \\
  --template data/sample_submission.tif \\
  --registry-manifest data/registry/manifest.json \\
  --out reports/uniqueness.json

The checker fails closed without a complete, hash-pinned manifest containing the literal lattice and all nine focus-site winners. See registry manifest requirements.

If the portal says “Predicted values must be in range [0, 1]”, do not rename or repackage the file and retry blindly. Preserve the erroring file and report, inspect every band and every pixel for NaN/Inf or values outside range, and compare the saved bytes against the official template. Never coerce a historical file silently.

What must happen before an estimate is possible

  • Restore and hash-check the official features, labels, existing-fault mask, and sample submission through the account's competition access.
  • Use the shared template's cached feature stack, `evaluate_holdout.py`, and `submission_writer.py`; do not create a private evaluator or infer a leader score from a projection.
  • Clarify the single-method lane, pre-register the hypothesis, run each feature-alone leakage canary, then evaluate whole-segment buffered holdout with pooled DTI and a 95% CI.
  • Run surface correlation before placement and final-dot overlap after placement against the refreshed registry. Any threshold failure is a logged negative and stops promotion.
  • Only after all scientific and byte gates pass may a separate slot selector consider a submission.
