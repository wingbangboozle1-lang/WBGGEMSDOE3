How a future file becomes eligible

  1. Assign the missing single-method lane, authenticate cached inputs, and freeze the complete registry.
  2. Run individual-feature leakage tests and buffered whole-segment hide-and-recover validation with the shared evaluator. Record pooled HOLDOUT-DTI, version, positives and 95% CI.
  3. Beat the current best reconstructed on identical folds with paired uncertainty. No numeric leaderboard forecast substitutes for this.
  4. Pass surface and final-dot registry gates without exempting controls. Exact bytes and equivalent pixel masks must both be checked.
  5. Use the pinned shared submission writer; reopen the saved TIFF and verify one band, finite values inside the footprint in [0,1], CRS, shape and geotransform. Resolve the official outside-footprint convention; do not silently clamp broken model inputs.
  6. The separate selector checks the live weekly cap and remaining slots. Only then may a release be labelled eligible and given a download button.
  7. On the official submission form choose the single-band .tif (or ZIP containing only that TIFF), paste its unique name and ≤140-character note, and upload. Save the returned receipt with the exact file hash. This project has not executed this step.

Range-error prevention

Never pass raw feature values or a no-data sentinel as prediction probabilities. The read-only format check rejects NaN/Inf inside the footprint and out-of-range values. It does not authorize an upload:

python scripts/check_candidate.py candidate.tif --template data/sample_submission.tif

Actual official portal acceptance is not proven by local validation. The rejected file was not provided, so its exact error cause is unknown.
