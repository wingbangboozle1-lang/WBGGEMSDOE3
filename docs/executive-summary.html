How a future submission becomes eligible

  1. Assign the explicit single method lane, authenticate data provenance and the shared template, and freeze the complete registry including calibration/null entries.
  2. Run each feature alone through the leakage canary. Treat AUC >0.90 as leakage until disproven.
  3. Use buffered whole-segment hide-and-recover folds; derive catalogue features from visible faults only, mask visible faults pixel-exactly, and evaluate with the shared pooled DTI (α=0.2, β=0.8, 300 m triangular kernel). Report evaluator version, withheld-positive count, and 95% CI.
  4. Require a paired improvement over a same-fold incumbent with a positive lower confidence bound. Check the continuous surface before placement and final dots against every registry raster; stop on either literal duplicate threshold.
  5. Reuse the shared submission writer. Reopen saved bytes and verify the actual sample grid, single band, finite/range policy, CRS, shape, transform, hash, and note length. Do not silently clamp invalid values.
  6. A separate selector checks the current organizer submission cap and remaining slots. Only an approved, fully gated artifact receives a release download link.
  7. Only then submit the exact hash through the organizer page, use a note of no more than 140 characters, and retain the matching receipt. This project has not performed that step.
