03 / SUBMISSION GUIDE

How a submission works.

All checks below must be run automatically on the exact saved bytes. A local format pass is not a performance or portal-acceptance guarantee.

01

Clear the scientific and uniqueness gates

Use one preregistered geological lane. Check surface and final dots against the complete current registry; any rank correlation above 0.90 or dot overlap above 70% within 3 pixels stops the run. Test each feature alone for leakage. Use the unchanged shared evaluator on buffered whole-segment, visible-only holdouts and beat the same-protocol current best.

02

Validate the exact TIFF

The official format requires one float32 layer in [0,1], EPSG:32611, 100 m pixels and matching bounds. The pinned owner mirror has shape 3,730 × 3,292; match its transform. Our conservative check additionally requires all raw values finite and the outside represented by an internal mask. Portal behavior for this encoding is not verified.

python scripts/validate_raster.py path/to/candidate.tif

The reported range error could involve NaNs, nodata sentinels, or other values; its actual cause was not observed. Do not assume replacing NaNs alone guarantees acceptance.

03

Wait for a separate selector decision

The experiment does not select or spend a weekly slot. Only a separate selector, after all evidence and the team's actual remaining quota are available, can authorize one. This project currently has no authorized candidate, name or upload note.

04

Submit only after authorization

Enroll and accept the competition rules. Give the validated file a unique filename. On DrivenData choose Submit → Make new submission, select that single-band .tif (or a ZIP with one .tif), and enter the optional note of at most 140 characters. Confirm the receipt and preserve it with the exact file hash. The user must perform the portal action; no credentials or slots are used here.
