Exactly how to submit

The LBCAL file is not cleared. The steps below apply to whichever file the repository decision clears (main dashboard), and only once the separate selector approves it within the weekly cap of 3 per entity (rules §3.2).

Steps

  1. Download the cleared .tif from the main dashboard. Do not open it and re-save it in GIS software, because that can add NaN or nodata values.
  2. Check it locally: python scripts/verify_submission.py <file.tif>. The template validator checks a single float32 band, 3730×3292, EPSG:32611, the sample transform, finite values in [0,1] everywhere, zero outside the footprint and zero on the catalogue.
  3. Go to DrivenData → Submissions, choose the .tif (or its one-file .zip) and upload it unchanged.
  4. Use the run card's submission_name as the unique name and its note (≤140 characters) as the note.
  5. Record the receipt (timestamp and public score) as ORGANIZER-CONFIRMED in registry/leaderboard.json.

Fixing "Predicted values must be in range [0, 1]"

The portal rejects any pixel outside [0,1]. Three things commonly put pixels there: NaN pixels inside the scored footprint, a nodata sentinel such as −3.4e38 or −9999 that is read back as a value, and float rounding above 1.0 in probability maps. This repository's writer (template submission_writer.write_submission) refuses to repair anything silently. It writes finite float32 values only (1.0 at dots, 0.0 everywhere else, including outside the footprint), sets no nodata tag, and validates the saved bytes. Files produced this way cannot trigger the error. To fix a third-party file, replace non-finite values with 0, clip to [0,1], and remove the nodata tag before uploading.
