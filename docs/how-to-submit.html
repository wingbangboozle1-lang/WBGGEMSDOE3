Why the earlier upload failed

The repository's previous file used NaN outside the study footprint. DrivenData's validator rejects some NaN-outside encodings with “Predicted values must be in range [0, 1]”. Two pieces of evidence settle the question in favour of zeros:

  • The official format text says “data outside the bounds is null or nan”, but every scored sibling file that produced a positive public score is a -zeros file (for example the 0.2778 champion …e5eb6e7e-zeros.tif). Acceptance is therefore NOT confirmed for either encoding. NaN-named sibling files also carry owner-reported scores (24 0.2477, 25 0.2600, 28 0.2710, 31 0.2708); none of these is an organizer receipt.
  • A NaN never compares inside an interval test, so any implementation that checks 0 ≤ v ≤ 1 elementwise will reject it. Zeros cannot trigger that error.
