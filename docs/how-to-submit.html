Why the earlier upload failed

The repository's previous file used NaN outside the study footprint. DrivenData's validator rejects NaN-outside encodings with "Predicted values must be in range [0, 1]": NaN never compares inside an interval test, so any elementwise 0 ≤ v ≤ 1 check rejects it. Zeros cannot trigger that error. Every scored sibling file that produced a positive public score is a -zeros file (for example the 0.2778 champion …e5eb6e7e-zeros.tif). Acceptance is therefore organizer-confirmed for the zeros encoding.
