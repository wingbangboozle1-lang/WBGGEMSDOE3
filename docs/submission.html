How to submit—only after clearance

DO NOT SUBMIT THE CURRENT TIFF

A GeoTIFF exists in the repository for audit/research, but its measured 97.87% lattice overlap fails the strict uniqueness gate, and required holdout/data/lane gates are missing. The audit-only download link is on the decision page; it is not a submission link.

Before an eligible release exists

  1. Resolve the method lane, authenticated training inputs, labels, fold definitions, complete registry, and incumbent baseline.
  2. Complete leakage canaries and the prescribed buffered whole-segment holdout. Record HOLDOUT-DTI with evaluator version, withheld positives, and 95% CI; keep it separate from organizer scores.
  3. Pass both continuous-surface and final-dot uniqueness gates, then validate the saved GeoTIFF against the authenticated sample and the shared writer.
  4. Obtain separate selector approval for a live weekly slot. No automatic upload or slot selection is available in this project.
  5. Download only the exact artifact hash authorized in the current run card. The current run card says negative; no authorized submission file is published.

Once a future candidate is explicitly approved

  1. Open the official DOE GEMS competition page and use its submission form.
  2. Select the approved single-band GeoTIFF (or a ZIP containing only that TIFF, if the official form permits it).
  3. Enter the exact run-card name and a note no longer than 140 characters.
  4. Save the returned receipt, timestamp, score, and exact file SHA-256. Only a receipt that binds the file to the result is ORGANIZER-CONFIRMED.

A local HOLDOUT-DTI is not an organizer score, and a successful local range check does not prove the portal will accept a file.

Range validation

Run the read-only validator against the official sample when available:

python scripts/check_candidate.py candidate.tif --template data/sample_submission.tif

It cannot authorize a submission. Never silently clip model output or substitute a repository template for the authenticated sample.
